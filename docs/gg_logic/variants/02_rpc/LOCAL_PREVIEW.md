# Локальная проверка новых RPC

**Актуальный порядок 13 октября:** применить согласованный
`iteration1/01_install.sql`, прочитать [iteration1/README](iteration1/README.md).
Бонусы теперь последним этапом: actions сохраняют временные клиентские100,
серверные исходные цифры доступны в server_*; медали до фиксации пустые.
Прежняя последовательность SQL02 бонусы/SQL03 медали ниже относится к раннему
плану и для текущего старта не применяется. Категорий теперь четыре.

Подготовлен отдельный entry point **lib/gg_v2_preview_main.dart**. Он использует
существующее подключение проекта Supabase, новые actions ggV2* и отдельный
listener gg:v2:stats. Старые локальные gg_* и main.dart не заменены.
Это экран сравнения расчётов, не визуальная копия native страниц FF.

Запуск из корня проекта после согласованного применения SQL-фаз:

```sh
flutter run -d chrome --target lib/gg_v2_preview_main.dart
```

По умолчанию RPC читает **prod**, test=false. Переключатель TEST/PROD относится
только к чтению: локальная сборка сама по себе не делает данные тестовыми.
Для личной строки, Meine Games и профиля ввести UUID существующего пользователя.
Без UUID доступен общий рейтинг. Можно передать UUID при запуске:

```sh
flutter run -d chrome --target lib/gg_v2_preview_main.dart \
  --dart-define=GG_USER_ID=UUID_СУЩЕСТВУЮЩЕГО_ПОЛЬЗОВАТЕЛЯ
```

В preview доступны только ranking/profile/history RPC. Нет создания игр,
приглашений, регистрации, claim или фиксации сезона. Сначала SQL 01 — проверка
доступа и JSON; 02 — бонусы/точные очки; 03 — сохранённые медали прошлого сезона.
Триггеры и Cron для этого ручного сравнения не обязательны. Кнопка обновления
перечитывает данные; после активации Broadcast работает тот же listener.

Открыть рядом Local Run текущего облачного FF и сравнить того же пользователя,
prod и тот же период. Старое приложение считает на клиенте, preview — на сервере.
Месяцы/+100/новые сезоны/MAP могут отличаться по согласованным исправлениям:
текущий FF не является эталоном для старых ошибочных формул.

Картинки временные, награды подписаны категорией/местом/годом. Финальные assets
владелец добавит в FF. Фильтры native UI и перенос соцсетей делаются отдельно
по NATIVE_BINDINGS, а не импортом preview вместо родной страницы.
