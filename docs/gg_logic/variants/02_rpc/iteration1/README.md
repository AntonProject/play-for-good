# Актуальный первый этап — 13 октября 2026

Этот каталог имеет приоритет над ранними `02_rpc/deploy` и общим install.sql.
Всё подготовлено **локально**. FF/Supabase этим чатом не изменялись.

## Очерёдность

1. Новые read RPC вместо загрузки всех игр/инвайтов для GoodGames/профиля.
   Все четыре категории временно сохраняются: valuable, active, generous, social.
   games.test и invites.test: NOT NULL DEFAULT false; старые записи/старые INSERT
   относятся к prod. Во всех новых вызовах/созданиях передавать Environment.test.
2. Проверка пользователем на существующих prod-данных, без создания новых игр.
   Оформление подключать к уже свёрстанным native виджетам по свежему снимку FF.
   Финальный макет — только выбранный завершённый сезон; для остальных фильтров
   текущий. Правила наград generous/social пока ожидаются.
3. Перенос +100 в БД **последним**: уточнить signup/admin/test происхождение,
   backfill, включить выдачу, отключить виртуальные +100, сверить сезонный топ,
   затем разрешить окончательное сохранение наград. Ранний bonus-first порядок
   из deploy не применять.

  Начало = предыдущая exclusive-граница, конец = начало + 10 месяцев exclusive.

Это заменяет раннее ежегодное сентябрь–июнь. Cron защищён от параллельного
планирования и повторов, догоняет календарь после паузы. Даты в UTC до отдельного
решения о продуктовом timezone. Админка в этот этап не добавляется.

## Контракт RPC / +100

Сервер возвращает чистые баллы игр/использованных инвайтов. Даже случайно
заполненный ledger игнорируется при signup_bonus_migrated=false.
В JSON добавлены signup_bonus_migrated, legacy_bonus_users_count, layout_mode
(`current`/`final`), results_finalized. Завершённый период и сохранённые награды —
разные признаки: до включения фиксации awards пустой.

Actions ggV2Rankings/ggV2ProfileStats при явном false сохраняют старую клиентскую
прибавку100 к личному Good Power/valuable.score **после фильтра**. Rank не меняется.
Общий Total получает 100 × число зарегистрированных users. Исходные цифры оставлены
в server_good_power/server_score/server_total_good_power* / server_value для сверки.
Это временное отображение, а не запись/история выдачи. MAP/generous/social/€nergy
не получают100. При true (либо старом JSON без флага) повторной прибавки нет.
В native Text привязать уже подготовленный JSON action и убрать отдельное +100
на этом Text: иначе именно при подключении action получится двойная прибавка.

Категории: MVP=Good Power; MAP=число completed игр; generous=сумма user/team/sieg/
additional donation money; social=число игр с sponsor_money>0. История social
сохраняет старую сортировку по lichtwatt, generous — по сумме €nergy.

## Среда на других экранах

В локальном основном экспорте добавлены фильтры games/invites во всех найденных
чтениях, включая Home, Energy, Organisation, диалоги, админские списки, Finish,
gamesCount. В stream установлен один серверный фильтр test; прежний completed/org
предикат сохранён локально в map, поскольку SDK принимает только один фильтр.
PlayPaymentPage INSERT games и InviteUser INSERT записывают Environment.test;
GamesRow/InvitesRow читают отсутствующий флаг как false.
Эти изменения ещё **не перенесены в cloud FF**. Старые gg_* вставки в основном
main.dart остаются черновиками; для RPC использовать отдельный preview target.

Read-only схема настоящей БД 13 октября: organization.test; transactions не имеет
test-колонки, но metadata содержит stripe_mode/is_live_payment. Платёжный API уже
получает test_mode. Finish получает транзакции по game_id. Новое поле транзакции
не создаётся этим пакетом. При игровом тесте сверить game.test и фактический
stripe_mode связанных транзакций; режим платежа не угадывать по debug-сборке.
Дедупликация InviteUser по email/обработка invite Auth-триггером пока глобальные:
перед тестом новых приглашений проверить эти серверные правила/unique constraints.
Ранговое чтение уже разделяет существующие invites.test.
