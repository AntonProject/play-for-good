# Вариант 3 — управление сезонами

Использовать `install.sql` и вариант 02 фронта + [общий START](../START.md).
Или базовый фронт с той же таблицей календаря, если оптимизацию не покупают.
На облаке ничего не применено. Два исходных сезона сохранены с датами ТЗ.

## Админка FF

Новая страница Seasons в существующей админке. Доступ скрыть для неадмина;
сервер отдельно проверяет owner-approved `gg_v2.season_admins`, UI-проверки
недостаточно. Добавлять доверенные UUID в roster может только владелец БД.

Custom Action `ggSeasonsAdmin(operation String,input JSON,test Boolean)` → JSON.

| Operation | Input | Ответ / поведение |
|---|---|---|
| list | `{}` | `seasons`: название, даты, year, finalized_at среды, locked |
| save | season_key, label, season_year, starts_on YYYY-MM-DD, last_day YYYY-MM-DD | saved; последний день включён |
| preview | season_key | MVP top_players + map.top_players, без сохранения результатов |
| finalize_test | season_key, test=true отдельным параметром | Только завершившийся тестовый сезон; повторный запуск не перезаписывает |

Поля формы: название, год плашки, начало, последний день. Внутренний ключ
уникален и не меняется при редактировании. Запретить end<start и пересечения.
Зафиксированный в любой среде сезон заблокирован для редактирования календаря.
Принудительное переоткрытие/ручной редактор победителей не входят.

`flutterflow/gg_season_admin_panel.dart` — готовый локальный пример формы,
списка, предпросмотра двух троек и тестового закрытия. В FF собрать такую же
форму вручную с `ggSeasonsAdmin`; при ошибке показывать ответ сервера.

## Автоматика и фильтры

Ежечасный Cron смотрит таблицу, закрывает обе среды отдельно по ends_at и
планирует следующий сезон. По предыдущему подтверждению повторение Sep 1–June 30;
это **10 календарных месяцев**, не непрерывные 9. Новый сезон не начинается
в момент создания записи. Автопланирование можно отключить в calendar_settings.
Следующий период, уже созданный/изменённый админом, не перезаписывается.
Если новые даты конфликтуют с текущим календарём — возвращается skipped,
нужно запланировать следующий через админку.

Пользовательские фильтры: два последних **начавшихся** сезона + прошлый месяц,
этот месяц, All-Time. Не загружать варианты из статического списка в FF.
`period='auto'` возвращает последний начавшийся: летом остаётся завершённый,
с датой начала нового — новый. Награды при этом остаются от закрытых сезонов.
Год золотой плашки берётся из season_year, а не парсится из названия.

Автообновление фильтров происходит при новой загрузке/возврате/resume и событиях
календаря. Начало сезона само не меняет строку таблицы, поэтому для страницы,
оставленной открытой через полночь, нужен refresh на границе календаря;
см. `gg_calendar_refresh.dart`. Возврат/resume уже покрывает listener.

Для теста: отдельные test-игры/инвайты/бонусы, известные очки и даты. Preview
позволяет проверить MVP/MAP без production-фиксации. Не менять prod-игры и
не редактировать итоговую таблицу вручную для проверки расчёта.
